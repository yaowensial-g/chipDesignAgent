# DMA Controller 功能规格（FS）

## 1. 文档信息

- 模块：`dma_ctrl`
- 版本：1.1
- 状态：示例基线
- 关联 AS：`dma_AS_v1.1.md`
- 关联 ICD：`dma_ICD_v1.1.md`

## 2. 模块职责

`dma_ctrl` 接收软件或上游模块提交的 DMA 搬运命令，按照命令顺序执行内存读写，并为每条已接收命令上报一次完成状态。

模块应完成：

1. 通过 Ready/Valid 命令通道接收 DMA 命令；
2. 缓存最多 8 条尚未开始执行的命令；
3. 按接收顺序执行命令，不允许乱序完成；
4. 将一次命令拆分为一个或多个不超过 256 Byte 的传输事务；
5. 通过完成通道为每条命令上报成功或错误结果；
6. 下游反压时保持命令和完成信息稳定；
7. Reset 后丢弃所有未完成命令，不生成完成上报。

## 3. DMA 命令格式

每条命令由以下字段组成：

| 字段 | 位宽 | 说明 |
|---|---:|---|
| `cmd_id` | 8 | 命令标识，完成上报原样返回 |
| `src_addr` | 64 | 源地址，必须按 4 Byte 对齐 |
| `dst_addr` | 64 | 目的地址，必须按 4 Byte 对齐 |
| `length_bytes` | 24 | 搬运字节数，合法范围 1～65536 |
| `irq_enable` | 1 | 完成后是否请求中断 |

地址未对齐、长度为 0 或长度超过 65536 的命令仍通过握手接收，但不得发起传输，必须上报 `INVALID_COMMAND`。

## 4. 命令接收行为

- 命令只在 `cmd_valid && cmd_ready` 的时钟沿被接收；
- `cmd_valid=1 && cmd_ready=0` 时，上游必须保持所有命令字段稳定；
- `cmd_ready=1` 仅表示当前周期可以接收命令，不能单独视为命令有效；
- 命令队列未满且模块不在 Reset 时，`cmd_ready=1`；
- 同周期允许一条新命令入队和一条待执行命令出队。

## 5. 执行行为

- 同一时刻最多执行一条命令；
- scheduler 仅在命令队列非空且当前没有活动命令时取出队首命令；
- 合法命令按最多 256 Byte 拆分事务；
- 当前事务成功后更新源地址、目的地址和剩余长度；
- 任一事务返回错误后停止该命令，不再发起后续事务；
- 一条命令结束后才能调度下一条命令。

## 6. 完成状态

每条已接收命令必须产生且只产生一次完成上报：

| 状态 | 编码 | 说明 |
|---|---:|---|
| `SUCCESS` | 0 | 全部数据搬运成功 |
| `READ_ERROR` | 1 | 读事务失败 |
| `WRITE_ERROR` | 2 | 写事务失败 |
| `INVALID_COMMAND` | 3 | 命令字段非法 |

完成信息包含 `completion_id`、`completion_status` 和 `completion_bytes_transferred`。完成通道的精确信号和握手规则在 ICD 中定义。

## 7. 性能要求

- 命令通道在队列有空间时支持每周期接收一条命令；
- 单条命令内部的连续传输事务之间最多允许一个控制周期间隔；
- 完成通道反压不得导致完成信息丢失或覆盖；
- 命令执行和完成上报必须保持接收顺序。

## 8. Reset 和异常

- `rst_n` 为低有效异步复位、同步释放；
- Reset 期间 `cmd_ready=0`、`completion_valid=0`；
- Reset 清空命令队列、活动命令和待上报完成状态；
- 外部总线超时由下游接口转换为读错误或写错误输入，本模块不自行计时。

## 9. 验收要求

- 覆盖单命令、多命令、队列满、并发入队出队；
- 覆盖合法长度边界和非法命令；
- 覆盖读错误、写错误及完成通道反压；
- 证明命令不会丢失、重复执行或乱序完成；
- 证明每条已接收命令恰好产生一次完成上报。
