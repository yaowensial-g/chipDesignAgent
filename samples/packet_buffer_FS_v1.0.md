# Packet Buffer 功能规格（FS）

## 1. 文档信息

- 文档类型：Functional Specification
- 模块名称：`packet_buffer`
- 版本：1.0
- 状态：示例基线
- 目标：为流式数据通路提供可配置深度的包缓存，并保证包边界、反压和错误状态正确传递。

## 2. 功能范围

`packet_buffer` 位于上游报文生产模块和下游报文消费模块之间。模块按拍接收数据，将完整报文暂存在内部存储中，并在至少存在一个完整报文时向下游发送。

模块应完成：

1. 接收基于 Ready/Valid 握手的数据流；
2. 使用 `in_sop` 和 `in_eop` 标识报文首拍和末拍；
3. 仅在完整报文已经写入后允许下游读取该报文；
4. 下游反压时保持输出数据及其控制信号稳定；
5. 缓存空间不足时对上游施加反压；
6. 统计已完整接收但尚未完全发出的报文数量；
7. 检测基本包格式错误，并将错误状态锁存到当前报文；
8. 支持软件清空缓存。

模块不负责：

- CRC 生成或校验；
- 报文内容解析；
- 跨时钟域传输；
- 数据加密、压缩或重排；
- 多优先级调度。

## 3. 参数

| 参数 | 默认值 | 约束 | 说明 |
|---|---:|---|---|
| `DATA_WIDTH` | 64 | 32、64、128 | 数据位宽 |
| `DEPTH` | 256 | 2 的整数次幂，且不小于 16 | 缓存深度，单位为拍 |
| `PKT_COUNT_WIDTH` | 8 | 能表示 0～DEPTH | 完整报文计数位宽 |

## 4. 时钟和复位

- 所有接口均工作在 `clk` 上升沿；
- `rst_n` 为低有效异步复位、同步释放；
- 复位后缓存为空，所有计数器和错误状态清零；
- 复位期间 `in_ready=0`、`out_valid=0`；
- 复位释放后的第一个有效时钟周期开始允许接收数据。

## 5. 输入流接口

| 信号 | 方向 | 位宽 | 说明 |
|---|---|---:|---|
| `in_valid` | input | 1 | 输入数据有效 |
| `in_ready` | output | 1 | 模块可以接收当前拍 |
| `in_data` | input | DATA_WIDTH | 输入数据 |
| `in_keep` | input | DATA_WIDTH/8 | 末拍有效字节掩码 |
| `in_sop` | input | 1 | 报文首拍 |
| `in_eop` | input | 1 | 报文末拍 |
| `in_error` | input | 1 | 上游标记当前拍存在错误 |

输入拍仅在 `in_valid && in_ready` 时被接收。

## 6. 输出流接口

| 信号 | 方向 | 位宽 | 说明 |
|---|---|---:|---|
| `out_valid` | output | 1 | 输出数据有效 |
| `out_ready` | input | 1 | 下游可以接收当前拍 |
| `out_data` | output | DATA_WIDTH | 输出数据 |
| `out_keep` | output | DATA_WIDTH/8 | 有效字节掩码 |
| `out_sop` | output | 1 | 报文首拍 |
| `out_eop` | output | 1 | 报文末拍 |
| `out_error` | output | 1 | 当前报文存在错误 |

输出拍仅在 `out_valid && out_ready` 时被消费。`out_valid=1 && out_ready=0` 时，所有输出载荷和控制信号必须保持稳定。

## 7. 控制和状态接口

| 信号 | 方向 | 位宽 | 说明 |
|---|---|---:|---|
| `flush` | input | 1 | 同步清空缓存，高电平保持一个周期 |
| `empty` | output | 1 | 缓存中不存在任何数据拍 |
| `full` | output | 1 | 缓存中没有可写空间 |
| `packet_available` | output | 1 | 至少存在一个完整报文 |
| `packet_count` | output | PKT_COUNT_WIDTH | 完整且未发完的报文数 |
| `format_error` | output | 1 | 检测到包格式错误，保持到 flush 或复位 |

## 8. 报文接收规则

1. 空闲状态下接收的第一拍必须带 `in_sop=1`；
2. 一个报文中除第一拍外不得再次出现 `in_sop=1`；
3. 单拍报文允许同时设置 `in_sop=1` 和 `in_eop=1`；
4. 非末拍要求 `in_keep` 全为 1；
5. 末拍的 `in_keep` 必须从最低位开始连续为 1，且不能全为 0；
6. 任意一拍的 `in_error=1` 都会使整个报文的输出 `out_error=1`；
7. 只有成功接收带 `in_eop=1` 的拍后，该报文才成为可读报文。

违反第 1～5 条时设置 `format_error=1`，同时把当前报文标记为错误，但仍然保存并输出该报文，避免数据通路失去同步。

## 9. 缓存和反压行为

- 模块必须预留一个存储位置，用于区分满和空；
- 当剩余空间为 0 时，`in_ready` 拉低；
- 同周期发生一次有效读和一次有效写时，可以保持占用量不变；
- 即使下游正在读取，未完整接收的报文也不能暴露给输出端；
- 当缓存中只有一个未完成报文时，`empty=0`，但 `packet_available=0` 且 `out_valid=0`；
- 不要求在报文开始时预知整包长度，因此超长报文可能占满缓存并对上游反压；上游必须遵守反压，不得继续发送。

## 10. Flush 行为

- `flush=1` 的时钟沿清除全部已缓存数据，包括未完成报文；
- Flush 优先级低于复位，高于正常读写；
- Flush 周期不接受输入，也不产生有效输出；
- Flush 后下一个周期恢复工作；
- Flush 清除 `format_error` 和当前报文错误状态。

## 11. 性能要求

- 无反压且缓存非空时，输出吞吐率应达到每周期一拍；
- 缓存非满时，输入吞吐率应达到每周期一拍；
- 输入和输出允许同周期独立握手；
- 不要求零周期旁路，首个完整报文的输出可以在其末拍写入后的下一周期开始。

## 12. 异常和边界条件

- 复位、Flush、缓存满、缓存空必须可预测；
- 指针回卷不得改变数据顺序；
- `packet_count` 不得上溢或下溢；
- 报文末拍写入与前一报文末拍读出同周期发生时，计数应正确更新；
- 输出报文顺序必须与完整接收顺序一致；
- 模块不得丢拍、重复拍或跨报文拼接数据。

## 13. 验收标准

设计和验证至少应证明：

1. 单拍、多拍以及最大长度压力场景数据一致；
2. 随机输入和输出反压下不丢数、不重数、不乱序；
3. 未完成报文不会输出；
4. 所有格式错误都能被检测并随包传播；
5. Reset 和 Flush 能从任意工作状态恢复为空闲；
6. 满/空边界、指针回卷和并发读写行为正确；
7. 参数组合 `DATA_WIDTH=32/64/128` 均可综合和验证。
